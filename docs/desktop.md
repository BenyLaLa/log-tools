# 图形安装版与服务器配置导入

发布文件：`LogTools-Setup-0.2.5-x64.exe`。适用于 Windows 10/11 x64，包含运行时和依赖，安装不需要 Python、pip 或外网。

## 首次安装

1. 双击安装 EXE，选择安装位置。默认安装到当前用户的 `%LOCALAPPDATA%\Programs\LogTools`，无需管理员权限。
2. 安装结束后打开 LogTools，点击“新增项目”手动填写，或点击“导入服务器配置”选择导出的 `*.logtools.json`。
3. 右侧可编辑项目名称、服务器地址、端口、账号和日志目录。输入自己的账号密码，或选择本机私钥；点击“保存项目设置”。同一服务器账号的项目默认共用凭据。
4. 点击“测试连接与日志读取”。它列出少量日志文件并试读一个字节，不保存或显示日志正文。
5. 打开“AI 客户端接入”，点击“验证 MCP 服务”；成功后选择“接入本机 Codex”或导出其他客户端使用的配置。
6. 重启 AI 客户端。之后无需保持配置窗口打开，也无需运行 `start.cmd`。

不需要 `known_hosts`、服务器主机公钥或管理员确认。SFTP 连接不校验服务器主机身份；仍使用账号密码或私钥登录，并保持传输加密。这样无法通过主机公钥识别服务器冒充。旧配置的 `known_hosts` 字段及旧共享文件的 `host_keys` 会被忽略，无需删除原文件。

安装可以完全离线。连接测试和实际下载需要访问公司服务器的网络/VPN；暂时不具备条件时可关闭窗口，稍后继续配置。

在“3 安装与数据”中可以设置日志缓存上限和单次完整下载上限，单位为 MiB。缓存上限填 `0` 表示不限，已有配置默认为不限。完整下载上限按本次请求的所有文件合计，也适用于本地导入。

点击“保存上限并检查缓存”会立即检查当前缓存。日志文件、片段、导入副本及其清单均计入。超限时按数据集创建时间从早到晚清理。正在下载或查询的数据等操作结束再处理。新数据集自身超过上限时会拒绝保存，保留已有数据集。两项上限对后续任务生效，切换缓存目录需要重启 MCP 客户端。

## 手动新增与编辑项目

- 点击“新增项目”清空表单，端口默认 22。填写项目名称、IP/主机名、账号及 SFTP 内日志目录，再点击“保存项目设置”。
- 在左侧选中项目即可编辑。修改项目名称会重命名原项目；其他项目和日志数据保持不变。名称已存在时会提示，不会覆盖已有项目。
- 项目名称使用 1–64 位英文字母、数字、下划线或连字符，并以字母或数字开头。服务器地址填写 IP 或主机名，不要加 `sftp://`；端口单独填写，日志目录以 `/` 开头。
- 仅改名称或日志目录时保留已有凭据。修改服务器地址、端口或账号后，不再引用旧连接的密码/口令；请填写新连接的凭据。新连接已在本机保存过凭据时可复用。
- 选择“密码认证”时，本机私钥框会禁用，无需填写。选择“私钥认证”后，私钥框和文件选择按钮才会启用。
- 保存配置后重启已经运行的 MCP 客户端，使新的项目名称和连接参数生效。

## 如何制作一键导入文件

已有脚本版可用配置时，在图形版中点击“迁移旧版配置”，选择原项目的 `config.json`。迁移不读取 `known_hosts`，直接保留服务器和日志目录、已配置环境变量/凭据引用、私钥路径、原下载缓存路径、本地导入白名单和查询限制；不修改旧配置，不复制原日志。

迁移前先停止旧版 MCP，避免尚未修复多进程协调的旧版本同时操作下载数据。迁移后点击“导出共享配置”，得到可交给其他人的 `servers.logtools.json`。

导出内容：项目别名、服务器地址/端口、账号、SFTP 可见日志目录、认证类型。**不包含密码、私钥内容、私钥本机路径、环境变量名、缓存路径或历史日志。** 文件会暴露内网地址与目录，只交给获授权的接收方；不要放进公开仓库。

接收者导入后，只需设置自己的凭据。同名项目覆盖会提示确认，其他项目不变。首次导入不需要额外确认主机指纹。项目名称、服务器地址、端口、账号和日志路径均可在界面中修改。

配置格式如下，将示例地址、账号和目录替换为实际值即可，无需填写主机公钥：

```json
{
  "format": "log-tools-profile",
  "version": 1,
  "servers": {
    "dev-project": {
      "host": "logs.example.internal",
      "port": 22,
      "username": "log_reader",
      "root": "/project",
      "authentication": "password",
      "credential_group": "default"
    }
  }
}
```

私钥认证用 `"authentication": "key"`，接收者导入后选择自己的私钥文件。私钥未加密时密码/口令框留空；有口令时在该框输入。该版本导入/导出界面支持 SFTP，原 FTP/FTPS 工具接口仍保留。

## 凭据、存储与升级

- 图形版新输入的密码/口令保存在当前 Windows 用户的凭据管理器中。JSON 只记录 `LogTools/...` 引用；不把密码写入环境变量或日志。不要与不受信任的人共享 Windows 登录账号。
- 旧配置的环境变量方式仍兼容，服务能读取配置明确引用的 Windows 用户/系统变量。
- 用户配置默认位于 `%LOCALAPPDATA%\CompanyLogTools\config.json`，与程序安装目录分离。
- 日志默认保存到该用户数据目录下的 `data/`；也可在“安装与数据”中选择其他磁盘。更改目录不搬迁或删除旧日志，运行中的 MCP 需重启。
- 使用同一安装器的新版覆盖升级即可。安装器保留用户配置、凭据和日志；卸载也默认保留这些数据。已有旧项目目录不会自动删除。
- Codex 接入只替换 `log-tools` 条目并备份原 TOML，其他 MCP 和设置保持原样。程序目录不变时无需重新接入。
- 多个新版 MCP 进程使用系统文件锁判断任务是否仍在运行，避免把另一对话的活跃下载误报为中断。进程意外退出后，下次查询可识别遗留任务。

## 从源码构建

构建机需要 Windows x64、Python 3.13、Inno Setup 编译器。构建依赖独立于终端用户安装；终端用户不需要这些工具。

```powershell
python -m venv .venv-desktop
.\.venv-desktop\Scripts\python.exe -m pip install -r requirements-desktop.txt
.\build-desktop.cmd -PythonPath '.\.venv-desktop\Scripts\python.exe' -IsccPath 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
```

产物位于 `dist/LogTools-Setup-0.2.5-x64.exe`。源配置、下载数据和 `.git` 不参与打包。安装器升级使用固定 AppId；发布时同步更新版本号并执行真实 EXE MCP 握手、离线安装、保留配置升级与导入测试。

此构建不配置远端 Linux 账号，也不会自动修改当前电脑的 Codex 配置；只有用户在界面中点击接入并确认时才会写入。

Codex 配置格式依据 [官方 MCP 文档](https://developers.openai.com/codex/mcp)。第三方依赖的许可文本随安装包保存在 `_internal/licenses`。

## 自动发现历史日志（0.2.3）

选中项目，打开右侧“历史日志扫描”页签，保存设置后点击“预览日志文件”。预览以目录树显示日志文件、大小和修改时间，并列出扫描遗漏提示；只读取元数据，不下载正文。“测试连接与日志读取”仍是快速检查，不代表扫描了全部历史文件。

默认开启历史发现，扫描项目根目录的当前日志，以及 `error`、`warn`、`info`、`debug` 内的历史日志。最大深度为 3（项目根目录为 0），匹配 `*.log*`，各层跳过 `target` 和 `.git`，最多检查 10,000 个目录项（包括不匹配文件）。不跟随 SFTP 子目录符号链接。服务器上的日志路径、账号权限和归档机制无需改动；原先不可读的目录仍会报告无法读取。

历史目录填写根目录下的文件夹名，以逗号分隔；留空表示只扫描根目录文件。可以改为 `archive` 等实际名称。文件匹配按文件名区分大小写；没有 `.log` 的压缩归档需要调整匹配规则，例如 `*.gz`。扫描时间预算为 20 秒，在目录项之间检查；正在等待的网络操作还受连接超时限制。

这些设置会随共享配置一起导入、导出。旧配置缺少 `discovery` 时自动采用上述默认值；无需重新导入服务器或填写密码。新增配置字段需要 0.2.3 或更新的程序，导入接收方也应升级。

每个项目的可选 `discovery` 字段如下，脚本版 config.json 和共享配置中的项目条目均支持：

```json
"discovery": {
  "enabled": true,
  "history_dirs": ["error", "warn", "info", "debug"],
  "max_depth": 3,
  "pattern": "*.log*",
  "exclude_dirs": ["target", ".git"],
  "max_entries": 10000
}
```

MCP `list_remote_logs` 不传递 `recursive`、`pattern`、`max_depth` 时使用项目设置。显式 `recursive: false` 只列出指定目录；指定 `directory: "error"` 时从该子目录扫描，深度仍按项目根目录计算。根目录扫描只进入配置的历史目录；显式子目录可用于临时缩小或改变范围，但仍遵守排除目录、根目录边界和深度限制。

结果包含 `relative_path`、`scanned_directories`、`skipped_directories`、`warnings`、`incomplete`。权限错误、数量/时间/深度限制都会标记 `incomplete: true`，不会当作完整扫描。按配置排除的目录只作为范围提示，不算扫描失败；诊断过多时 `diagnostics_truncated` 会提示显示不完整。

`limit` 为每页文件数量（1–1000）。有下一页时使用同一 MCP 会话、相同 `server` 及返回的 `next_cursor` 再次调用；游标页忽略其他扫描参数，允许调整 `limit`。分页基于同一次扫描的元数据快照，不重复访问服务器；快照最多保留 5 分钟，每个进程最多 8 份，重启或被后续扫描淘汰后需重新扫描。`truncated` 兼容旧客户端，表示“扫描不完整或还有下一页”；是否真的漏扫以 `incomplete` 为准。扫描期间源目录仍可能变化，快照不是服务器文件系统的原子快照。

文件名日期和修改时间仅用于选择候选日志，最终按日志内容时间核实。AI 查最新异常时先看当前错误日志，证据不足再扩展历史；按日期、请求标识排查时选择相应归档及日志级别，并明确实际查询范围。发现文件不会自动下载，也不会自动去重历史下载缓存；下载仍需要显式选择路径。

升级后重启正在运行的 MCP 客户端，让新工具参数和项目设置生效；安装路径未改变时无需重新接入。

在“4 片段检索”中选择候选文件和筛选条件，预算默认取当前配置上限。详见 [片段检索流程](fragments.md)。
